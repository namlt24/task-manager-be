A. MỤC TIÊU GIAI ĐOẠN 1
--------------------------------------------------------------------------
Xây dựng nền tảng xác thực & người dùng cho ứng dụng task manager cá nhân
đa người dùng:
  - Đăng ký / Đăng nhập / Đăng xuất
  - JWT access token + refresh token (có rotation)
  - Phân quyền RBAC (ROLE_USER / ROLE_ADMIN)
  - Quản lý hồ sơ cá nhân (xem/sửa/đổi mật khẩu)
  - Giao diện Angular: login, register, layout, dashboard + bảo vệ route

B. CÔNG NGHỆ SỬ DỤNG
--------------------------------------------------------------------------
Backend : Java 17, Spring Boot 3.4.1, Maven 3.9
DB      : PostgreSQL 16 + Flyway (migration)
Token   : Redis 7 (lưu & xoay refresh token)
Security: Spring Security stateless + JWT (jjwt 0.12), BCrypt, RBAC
Mapping : MapStruct 1.6
API docs: springdoc-openapi (Swagger UI)
Frontend: Angular 18 (standalone components + signals), RxJS, SCSS
Hạ tầng : Docker Compose (postgres, redis, mailpit)

Lưu ý: Kế hoạch draft ghi Java 21/Angular 19 nhưng đã hạ xuống 17/18 cho
khớp toolchain máy. Bucket4j (rate-limit) tạm gỡ, để lại Giai đoạn 7.

C. BACKEND - ĐÃ LÀM
==========================================================================

1) ENTITY & DATABASE
   - User  : id, email (unique), password_hash (BCrypt), full_name,
             avatar_url, timezone, enabled, roles (N-N), created/updated_at
   - Role  : id, name (enum RoleName: ROLE_USER, ROLE_ADMIN)
   - Bảng nối user_roles
   - Migration Flyway: V1__init_auth.sql
       + tạo bảng roles, users, user_roles
       + index lower(email)
       + seed sẵn 2 role: ROLE_USER, ROLE_ADMIN
   - Base class Auditable (created_at / updated_at tự động qua JPA Auditing)

2) SECURITY / JWT
   - SecurityConfig: stateless, CORS, CSRF off;
       permitAll: /v1/auth/**, swagger, actuator/health
       còn lại: yêu cầu đăng nhập
   - JwtService:
       + access token (mặc định 15 phút) chứa userId, email, roles
       + refresh token (mặc định 7 ngày) chứa jti (UUID) duy nhất
   - JwtAuthenticationFilter: đọc Bearer token -> set SecurityContext
   - CustomUserDetailsService + AppUserDetails (adapter UserDetails)
   - RestAuthenticationEntryPoint: trả 401 dạng ProblemDetail
   - SecurityUtils.getCurrentUserId(): lấy user đang đăng nhập
   - RefreshTokenStore (Redis, key "refresh:{userId}"):
       whitelist + ROTATION (mỗi lần refresh sinh token mới, token cũ vô hiệu)
       logout -> xóa key (revoke)

3) CÁC API ENDPOINT (prefix /api/v1)
   POST /auth/register        -> 201 + tokens (gán ROLE_USER)
   POST /auth/login           -> 200 + tokens
   POST /auth/refresh         -> 200 (xoay token; token cũ bị vô hiệu)
   POST /auth/logout          -> 204 (revoke refresh token)
   GET  /users/me             -> 200 hồ sơ user hiện tại
   PUT  /users/me             -> cập nhật fullName / timezone / avatarUrl
   PUT  /users/me/password    -> đổi mật khẩu (kiểm tra mật khẩu cũ)

4) XỬ LÝ LỖI CHUẨN
   - GlobalExceptionHandler (@RestControllerAdvice) trả RFC 7807 ProblemDetail
   - Exception riêng: ResourceNotFoundException, BadRequestException,
     ConflictException
   - Bean Validation (@Valid) trên các DTO request

1) TaskManagerApplication.java

3) common/exception/*

4) config/AppProperties.java

5) config/SecurityConfig.java
   "Bộ não" bảo mật:
   - Tắt CSRF, bật CORS, đặt session = STATELESS (không lưu session, chỉ JWT).
   - Khai báo route công khai (/v1/auth/**, swagger) vs route cần đăng nhập.
   - Cắm JwtAuthenticationFilter vào chuỗi lọc.

6) config/OpenApiConfig.java

8) security/JwtAuthenticationFilter.java
   Chạy MỖI request: đọc header "Authorization: Bearer ...", nếu là access token

K. CÁC LUỒNG CHẠY CHI TIẾT
==========================================================================

--- LUỒNG 1: ĐĂNG KÝ (REGISTER) ------------------------------------------
  1. User nhập họ tên/email/mật khẩu ở RegisterComponent, bấm "Đăng ký".
  2. AuthService.register() POST /api/v1/auth/register.
     (interceptor KHÔNG gắn token vì đây là endpoint auth)
  3. AuthController -> AuthService.register():
       - Kiểm tra email đã tồn tại chưa (nếu có -> ném ConflictException -> 409).
       - Băm mật khẩu bằng BCrypt, gán ROLE_USER, lưu User vào Postgres.
       - issueTokens(): JwtService sinh access + refresh; RefreshTokenStore lưu
         refresh vào Redis.
       - Trả 201 + AuthResponse (2 token + thông tin user).
  4. FE: TokenStorageService lưu 2 token; cập nhật signal currentUser;
     điều hướng tới /dashboard.

--- LUỒNG 2: ĐĂNG NHẬP (LOGIN) -------------------------------------------
  1. LoginComponent gửi email + mật khẩu.
  2. AuthService.login() POST /api/v1/auth/login.
  3. AuthService.login():
       - AuthenticationManager xác thực qua CustomUserDetailsService + BCrypt.
       - Sai thông tin -> BadCredentialsException -> 401.
       - Đúng -> issueTokens() (sinh token mới, GHI ĐÈ refresh token cũ trong
         Redis = rotation), trả 200 + AuthResponse.
  4. FE lưu token, set currentUser, vào /dashboard.

--- LUỒNG 3: TRUY CẬP TÀI NGUYÊN CẦN ĐĂNG NHẬP (vd /users/me) -------------
  1. Component/Service gọi GET /api/v1/users/me.
  2. auth.interceptor gắn "Authorization: Bearer <access>".
  3. BE: JwtAuthenticationFilter đọc token -> hợp lệ -> nạp user -> đặt vào
     SecurityContext.
  4. SecurityConfig thấy đã xác thực -> cho qua tới UserController.
  5. UserService lấy user theo SecurityUtils.getCurrentUserId(), UserMapper
     đổi sang UserDto (ẩn password) -> trả 200.
  * Nếu KHÔNG có/đã hết hạn token: filter không set context ->
    RestAuthenticationEntryPoint trả 401 (xem luồng 4).

--- LUỒNG 4: TỰ ĐỘNG LÀM MỚI TOKEN KHI 401 (REFRESH) ---------------------
  1. Access token hết hạn -> request bất kỳ nhận 401.
  2. auth.interceptor bắt 401 (không phải endpoint auth, còn refresh token):
       - Gọi AuthService.refresh() POST /api/v1/auth/refresh với refresh token.
       - Nhiều request 401 đồng thời -> chỉ 1 lần refresh, số còn lại chờ kết quả.
  3. BE AuthService.refresh():
       - Parse refresh token; phải đúng loại "refresh".
       - RefreshTokenStore.isValid(): token có khớp token đang lưu ở Redis không.
         (token cũ đã bị xoay -> không khớp -> 401)
       - Hợp lệ -> issueTokens() (sinh cặp mới + ghi đè Redis), trả 200.
  4. FE lưu token mới rồi PHÁT LẠI request gốc với access token mới -> thành công.
  5. Nếu refresh cũng 401 (token bị revoke/hết hạn) -> xóa token, về /login.

--- LUỒNG 5: ĐĂNG XUẤT (LOGOUT) ------------------------------------------
  1. Bấm "Đăng xuất" ở topbar -> AuthService.logout() POST /api/v1/auth/logout.
  2. BE: AuthService.logout() -> RefreshTokenStore.revoke() xóa key Redis của user
     => refresh token không còn dùng được nữa.
  3. FE: xóa token khỏi localStorage, đặt currentUser = null.
  4. authGuard chặn các route nội bộ -> tự về /login.

--- LUỒNG 6: BẢO VỆ ROUTE PHÍA FE (GUARD) --------------------------------
  - Vào "/" hoặc "/dashboard": authGuard kiểm tra có token không.
      Có -> cho vào; Không -> chuyển hướng /login.
  - Vào "/login" hoặc "/register" khi đã đăng nhập: guestGuard -> đẩy về /dashboard.

--- TÓM TẮT VÒNG ĐỜI TOKEN ------------------------------------------------
  access token (15')  : đính kèm mọi request; hết hạn thì dùng refresh để lấy mới.
  refresh token (7d)  : chỉ dùng ở /auth/refresh; mỗi lần dùng bị XOAY (token cũ
                        chết); lưu ở Redis để có thể thu hồi (logout).
